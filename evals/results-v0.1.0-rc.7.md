## 规则与文本场景检查

方法：实施者逐项对照现行 Skill 和场景输入，推导参考使用、输出状态、候选集合、规格判断及下一动作，再比较预期行为。下面为规则自检与文本推演，不是独立模型行为实测；图片、工具返回、失败和 PASS 均为场景假设。

| 场景 | 本次推导与判断 |
|---|---|
| E16 A／D | 各具名对象首次生成前取得、查看并使用对应实物参考；背景和局部保持一致。普通装饰不逐项取参考，准确且满足其他标准的候选正常通过。 |
| E16 B／C | 参考不足继续查找或调整为有依据的示意表达；错对象局部、构件数量及残损误绘需要定位与修复，主体大体正确不能抵消局部误导。Reviewer 使用同一必要依据查看实际候选。 |
| E17 返回阶段 | 08 页 v2 成功；03 页不可读、07 页缺失立即记为失败或未完成，不按返回顺序错配，不以旧 v1 填补必要修订。返回文件实际对应另一页时同样不能更新成功。此时不能视为完整候选。 |
| E17 完成阶段 | 修复成功后，03、07、08 页用 v2，其余页面用 v1，按 01—08 排列。全新 Reviewer 复审该候选，验收及打包沿用对应集合；漏页、重复及混入旧版修正文件集合，不擅自改动验收页面。 |
| E18 A／D | 1086 × 1448 为 3:4，清晰且满足其他标准时保留原生尺寸并通过，无需默认缩放。后续修订同样检查；最终两种合格尺寸分别报告，不误称整套均为默认像素。 |
| E18 B／C | 1080 × 1448 比例不符、540 × 720 的模糊文字需要调整制作，不能仅拉伸或放大后通过。明确要求 1200 × 1600 时，1206 × 1608 即使同为 3:4 也须统一到精确尺寸并复查，Reviewer 检查最终版本。 |
| E10 A／B／C | 用户仅回复“通过”后完成交付并主动自检；有依据的问题提出改进，无实质问题简短结束。现有规则执行遗漏如实归因，不重复新增流程或重开已验收候选。 |
| E01—E03 | 目的地研究、具体行程确认及确认后直接制作仍成立；E02 按修订尺寸规则判断。固定条件、动态依据、知识内容及路线时间要求继续贯穿成品。 |
| E04—E05 | 一名默认或用户指定数量的全新 Reviewer 检查实际完整候选；复审覆盖变更影响与整套关系。本版增加必要参考、清单和有效规格核对，角色与循环不变。 |
| E06—E09 | PASS 后保持候选稳定等待验收；用户反馈触发整套方向性检查及按实际问题修复；能力缺口不能虚报 PASS；进度问答后继续，关键约束变化沿用集中确认。 |
| E11—E12 | 顺路与必要折返判断不变；E11 两变体仍分别于 11:45、14:30 到终点。E12 南门入、依次三区、北门出，内部步行 40 分钟、观察 60 分钟、接驳共 30 分钟。 |
| E13—E14 | 馆内或自备用餐、禁携食与不可重入冲突、未知信息处理不变；错误路线、用餐或时间预算修复按实际影响同步页面，合理方案正常通过。 |
| E15 | 前夜睡眠和完整时间预算不变：A 08:00 起床、09:30 入馆、17:30 离馆；B 17:35 离馆；C 馆内休息至 18:00 可行、返酒店至 19:15 冲突；D 仅剩 5 小时净游览需确认调整；E 无依据压缩不通过，F／G 沿用用户需求优先及明确睡眠假设。 |
