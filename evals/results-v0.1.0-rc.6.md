## 规则与文本场景检查

方法：实施者对照当前 SKILL 和 E01—E15 的输入条件，推导可行安排、时间、条件优先关系、关键取舍、下一动作、角色和等待节点，再与预期比较。E15 用一次性 Python 算术核对，其他路线沿用给定通路和时长计算。以下是规则自检与文本推演，不是模型行为实测、真实旅行研究或独立 Reviewer 检查；候选图片、缺陷和 PASS 均为场景假设。

| 场景 | 本次推导与判断 |
|---|---|
| E01 A／B／C | 目的地未知先比较，已知则研究组合；“你决定”和清单不代替具体行程确认，确认后制作。与现有节点一致。 |
| E02 A／B／C | 确认后直接制作完整套图；尺寸及用户简洁表达要求优先，所依赖用餐条件仍需核实。新增睡眠、停留与净游览及补给准备的成品自检，不增加样张确认。 |
| E03 | 固定酒店、活动与交通贯穿方案；前夜及睡眠参与次日推导，真实约束冲突沿用确认机制；动态事实有依据，未知给复核动作。知识及跨页要求仍有效。 |
| E04 A／B | 一名默认或用户指定两名全新 Reviewer，检查实际完整候选及全部 PASS 条件；新增节奏与时间要求纳入判断，角色与实际图像仍为场景假设。 |
| E05 | 按实际及关联影响修复，提交完整最新候选，全新 Reviewer 正式复审；无实质问题即转等待用户验收。 |
| E06 | 系统 PASS 后候选稳定，提交成品并等待；沉默与进度询问不构成用户验收或重启修复。 |
| E07 | 用户反馈更新质量方向，检查整套同类和关联问题，修复后沿用独立审核及再次验收。 |
| E08 A／B／C | 共享问题统筹处理，无效修复重新诊断；缺实际图像或独立 Reviewer 时准确说明，不能宣称系统 PASS。 |
| E09 A／B／C | 进度问答后继续已有授权；关键约束变化形成具体取舍并集中确认，重算受影响安排。 |
| E10 A／B | 用户明确通过才最终交付；有证据才提出 Skill 改进，无实质问题则结束，建议不自动触发修改。 |
| E11 一／二 | 一：顺路步行 45 分钟、参观 120 分钟，11:45 到终点；反序步行 75 分钟无收益。二：预约与开放造成必要折返，等待、休息和午餐均有依据，14:30 到终点。个人默认不排斥必要等待。 |
| E12 | 南门入、依次三区、北门出；内部步行 40 分钟、观察 60 分钟、两端交通共 30 分钟，总 130 分钟。入口与实际通路有效，通行与观察分别计时。 |
| E13 A／B | 固定 12:00—13:00 用餐源自明确要求。11:55 离展区，12:00—12:45 用餐，12:50 返回；净参观 6 小时，用餐及绕行 55 分钟，15:55 结束。A 馆内，B 提前备餐并在指定区食用。 |
| E13 C／D | C 识别餐饮不可用、禁携食及不可重入与中途用餐需求冲突，具体缩短或拆分取舍沿用确认；D 查缺失信息，未知仍保留不确定性，可采用已有依据的自备方案。 |
| E14 A—D | 错误入口、虚构通路和不可重入安排为实质问题；改北门出可减少内部 20 分钟及外部 30 分钟，相关导览、总览与交通同步修复。必要折返和合理表达形式通过。 |
| E14 E／F／G | E 指出睡眠、净游览及漏计耗时的实质影响，按实际范围重算和同步页面，沿用必要确认及全新 Reviewer 复审。F 合理默认、用户休息和固定午餐通过；G 已接受的 5 小时重点参观符合真实交通约束，通过后稳定等待用户验收。 |
| E15 A | 23:30 返宿、00:00 就寝、08:00 起床、08:45 出发、09:15 到馆排队、09:30 入馆。净游览 360 分钟＋非游览 120 分钟＝停留 480 分钟，17:30 离馆。 |
| E15 B | 备餐增加晨间 20 分钟，无供餐排队减少停留 15 分钟；09:05 出发、09:50 入馆、停留 465 分钟，17:35 离馆。提醒入场前准备并在指定区用餐。 |
| E15 C | 用户要求馆内休息 30 分钟：18:00 离馆，已计 20 分钟缓冲，按给定条件可行。返酒店变体另需 105 分钟至 19:15，超过开放时间，提出具体调整并沿用必要确认。 |
| E15 D | 09:30—16:30 可停留 420 分钟，减非游览 120 分钟仅剩净游览 300 分钟，缺 1 小时；保持睡眠及固定活动条件，说明精选重点或另日参观取舍并等待必要确认。 |
| E15 E | 提前至 07:00 起床仅睡 7 小时；无依据缩至 5 小时参观不符原目标；把 6 小时停留当净游览会漏掉 2 小时非游览。恢复按有效需求核算。 |
| E15 F／G | F 明确固定用餐需求优先，沿用 E13。G 说明规划睡眠假设，实质影响方案时集中询问；不把场景数值写为通用默认。 |

E15 A 的供餐窗口也能满足：例如 09:30—09:40 通行，09:40—12:00 净游览，12:00—12:05 前往餐厅，12:05—12:20 排队，12:20—13:05 用餐，13:05—13:10 返回；余下净游览 220 分钟、通行 20 分钟和缓冲 20 分钟可在 17:30 前完成。该示例只证明给定窗口存在可行安排，实际午餐仍随进度、饥饿和供餐安排。

结论：六项偏好在规划、自检、审核及场景中的对应关系一致，E15 和 E14 扩展及 E01—E14 回归文本检查通过；规则明确区分个人默认、具体需求及真实约束，合理方案通过。此结论不证明工具环境中的模型一定如此执行，也不是旅行攻略的系统 PASS。
