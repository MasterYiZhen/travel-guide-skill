## 要求来源、适用条件与覆盖

来源仅为本版用户确认要求：

- **附件一：产品定义。** 图片为主、手机竖向使用，内容与知识覆盖、可靠动态事实、条件传递、图文和跨页一致、参考目标、1080 × 1440 默认规格及有范围的内容偏好。
- **附件二：流程与自动推进。** 研究推荐、明确确认景点与行程、直接套图、审核修复、等待用户、反馈整套检查、最终交付和按需流程改进，以及进度沟通和关键约束变更。
- **附件三：独立审核与质量阈值。** 每次一名全新 Reviewer、职责分离、实际完整候选、PASS 标准、影响范围复核、无效修复诊断及能力缺口。
- **附件四及用户确认的修订计划。** 正向精炼、自主实现、当前用户要求优先、旧资料清理；规则需有已确认依据；本轮采用结构与文本场景检查，真实旅行验证另行记录。
- **修订计划保留的适用边界。** 显式调用、全新连续任务，不增加跨会话恢复机制；维持两文件安装包与版本化发布方式。

来源名称用于定位本版会话要求；下表已记录其实际含义，运行时不需要读取附件或会话历史。旧资料不作为新增规则来源。官方 [Prompting best practices](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices)已在规划时读取，用于落实主动推进、指令优先级、按需委派、适度验证和清楚表达，不新增旅行确认节点或模型 API 配置。

### 确认、检查与停止条件审核

- **确认：** 具体景点与行程确认、系统 PASS 后用户验收是已确认节点；关键行程或约束变化时集中决定。普通排序、拆分和制作不增设确认，已有有效确认直接沿用。实质信息缺口询问服务于形成方案，不新增阶段审批。
- **检查：** 制作者自检、独立正式审核按已确认职责分工；首次完整候选完整检查，内部修复按实际影响复核并结合整套关系，用户反馈方向覆盖所有图片。检查与修改范围分开，没有设置固定次数或额外视觉审核层。
- **停止：** 无实质问题时转入系统 PASS 后的用户验收等待；用户明确通过后交付并自检；无改善先调整方法，真实能力缺口如实说明。没有新增样张放行、无意义轮数上限或按进度询问结束任务的条件。
- **规则合并：** 产品标准集中定义，审核以结果阈值判断，反馈流程引用同一审核循环；历史视觉负面清单、逐项强制下游重算表、修图技巧和一次性方法不进入新版规则。

## 行为场景文本推演记录

方法：实施者逐项读取 [E01—E10](evals.md) 的输入，结合当前 `SKILL.md` 推导下一动作、等待节点、角色和结束条件，再与场景预期及已确认要求比较。下表是文本推导结果，没有运行旅行任务、测试用户对话或子 Agent。所有图片、缺陷、PASS 和用户通过均为场景假设。

| 场景 | 文本推导出的路径与判断 | 比较结果及限制 |
|---|---|---|
| E01 A／B／C | 未知目的地先比较；已知目的地按条件组合。三种输入都先形成具体方案，未有行程确认时等待；未把一般授权或清单完整当作行程通过。 | 文本一致；未真实研究目的地。 |
| E02 A／B／C | 已确认行程直接完整制作与自检；参考参与目标而不增加门禁；默认尺寸、指定尺寸和寄存例外分别生效。内容偏好按默认／当前要求判断。 | 文本一致；未出图，尺寸和视觉效果未实测。 |
| E03 | 固定安排作为约束，未知展出和票权保持待核实并给动作；知识覆盖背景、价值和观察点，图文化保持跨页事实。 | 文本一致；未核实真实场馆或票务。 |
| E04 | 当前候选交全新 Reviewer，提供目标约束参考，完整高清检查后依全部阈值判断；旧 PASS 不替代检查。 | 文本一致；未创建 Reviewer 或查看实际图片。 |
| E05 | 制作者修时间错锚、文字及引线关联问题，自检后交另一新 Reviewer；复核涵盖关联页，结合完整候选判断，有问题继续，无问题转 E06。 | 文本一致；未实际修图或复审。 |
| E06 | 系统 PASS 后提交最新整套并等待；沉默和进度询问均不构成用户通过，也不触发重做。反馈转 E07，通过转 E10。 | 文本一致；PASS 为输入假设。 |
| E07 | 先把反馈理解为解释和观察价值方向，检查全部图片；将同类问题及其他行动遗漏纳入实际修复，重新审核后提交最新整套。 | 文本一致；未发生真实反馈、扫描或修复。 |
| E08 A／B／C | A 调整受共享问题影响的套图；B 无改善时重新诊断换方法；C 准确报告能力缺口，不宣称 PASS。 | 文本一致；未验证工具能力或修复效果。 |
| E09 A／B／C | A 汇报后继续；B 形成具体取舍后等待关键约束决定；C 取消景点后重算受影响住宿返程，仍需变更其他关键约束时集中决定。 | 文本一致；没有执行实际方案变更。 |
| E10 A／B | 用户通过后完成最新交付，再自检流程；A 有证据时提出含四项说明的改进方案，B 无实质问题简短结束，均不自动修改 Skill。 | 文本一致；通过及问题证据为输入假设，未模拟真实用户验收。 |

10 组场景的文本路径与当前要求一致。本结论不说明模型在真实工具、图片和长任务中一定遵守；实际独立 Reviewer 新建、图片检查覆盖与修复结果待真实任务观察。
