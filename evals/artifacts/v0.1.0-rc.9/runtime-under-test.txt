# Travel Guide Skill v0.1.0-rc.9

## 产品目标与适用范围

默认交付以高清竖向图片为主要载体、适合手机查看的旅行攻略。用户凭攻略能够准备预约，完成每日行程与交通衔接，并识别、理解和观察现场的重要景点、建筑、遗址及具名藏品。用户当前要求优先于本文的默认标准与偏好。

适用于用户主动调用后的当前连续任务，任务内的反馈与修订沿本流程继续；不承担中途接手或跨会话恢复。研究工具、制作方法、中间材料的组织、图片数量与内容拆分均由任务决定，运行流程自包含，不依赖历史旅行资料或固定城市模板。

## 内容与视觉标准

以下是成品的默认质量目标，也是制作自检与正式审核的共同依据。

- **覆盖：** 图片覆盖整体与每日安排、关键交通与出入口衔接、预约购票渠道、操作时间与适用权益、重点对象讲解，以及作息、补给和必要备选。关键行动信息进入攻略图片，方便现场查找。
- **讲解深度：** 默认提供详尽、有现场观察价值的讲解。重点景点、建筑、遗址和具名藏品依其自身特点，讲清身份、时代背景、用途与工艺、重要性，以及造型、纹饰、铭文、结构等值得现场观察的细节。以用户能否理解对象并找到观察点判断充分程度，展开方式与篇幅由对象及信息量决定；用户明确要求简略时相应收敛，仍保留行动与重点识别信息。
- **图文融合：** 图片、文字、标注和游览动线围绕具体内容，共同承担识别、解释与行动指引。路线图与讲解图具有同一系列的精细程度，不同内容采用合适构图；文字准确通顺、字形正确，同级字体关系协调，局部修订与周围画面自然衔接；全貌、局部、说明及引线对应同一对象。
- **动线与时间：** 全天动线及大型或复杂景点的内部动线符合实际空间与通行条件，说明入口、参观顺序、重点看点、区域连接与出口，并接入前后行程。成品清楚表达关键起止时间、停留与净游览时长的区别、补给节点及必要准备，时间与前后衔接一致。
- **参考与认可维度：** 识别性插图与可靠实物参考一致。用户认可的参考成品按其被认可的维度定义目标：改视觉时保留已认可的内容深度，改内容时保持仍有效的视觉目标；旧参考的篇幅与页数不限制新内容，其中的旅行事实另行核实。
- **规格：** 默认图片参考尺寸 **1080 × 1440 px**，保持 **3:4**，接受同等比例的小幅偏差，不设固定百分比容差；以手机阅读、文字清晰和细节可辨为依据，合格的原生输出保留实际尺寸。用户明确要求精确像素时严格遵守。主要信息方便查找，细节可放大阅读。
- **一致性：** 用户已确认的条件贯穿行程与成品；内容压缩、拆分、图文化和修复保持时间、空间、对象及相关事实在跨页与图文间一致。

成品质量以实际高清页面、必要局部和整套关系的检查为依据。知识稿正确、文本提取成功、工具返回完成或历史 PASS，均不能替代实际成品检查。

以下为默认内容偏好，具体旅行要求及所选行程实际依赖的条件优先：路线示意说明顺序、空间与关键衔接，精确导航使用导航软件；餐饮简洁提示用餐节点和附近区域；默认省略卫生间、饮水点、便利店及行李寄存信息；所选行程实际依赖的供餐、携食、再次入场等补给与服务条件进入相关图片或准备提示；预约表达操作方式与时间，不记录“已预约／未预约”等易过期状态。

以下为个人默认节奏偏好，具体旅行中明确提出的用餐、休息、体力和同行需求优先：保障夜间充足睡眠，白天以连续游览和途中补给为主，无需专门安排午休或返回酒店休息；酒店按需安排入住、放包、退房等必要事务；午餐随参观进度、饥饿程度和供餐条件灵活安排。

## 流程与自动推进

八步依次推进：研究推荐 → 确认行程 → 制作完整候选 → 独立审核修复 → 等待用户验收 → 反馈与再次验收 → 最终交付 → 流程自检。日常研究、制作、检查与修复在已有授权内持续推进，普通排序、内容拆分和制作选择不另设确认节点；缺失信息实质影响方案时集中询问，客观事实通过研究解决。用户询问进度时简短汇报真实状态，随后保持当前阶段应有的继续执行或等待验收，不把询问视为反馈或通过。

### 1. 研究与推荐

根据出发地、日期与可用时间、预算、兴趣、节奏、同行人和行动限制，以及已确认的预订、交通、活动与必去／不去条件开展研究。目的地未知时比较现实可行的候选；目的地已知时研究景点与行程组合。给出有判断的推荐、景点价值、组合理由和主要取舍。

准备重点对象的知识依据、实物参考与现场观察点。对象知识、外观依据，以及旅行日期的展出、开放、入场、票务和交通状态分别核实，采用可靠且适时的依据；拟用备选票种核实日期适用性与实际入场权益。未确定的信息保留不确定性，并给出可执行的复核或调整办法，不由“馆藏有此对象”推断当天必能观看。

依据实际位置、可用出入口、内部通路及开放预约条件比较全天与内部路线，优先衔接顺畅、少绕行和少重复路段的安排；必要折返说明收益或现实约束。大型或复杂景点按实际入口、出口、分区、重点看点及连接关系规划连贯的参观顺序，并与前后行程衔接。

结合前夜活动结束、返宿、睡前准备、睡眠需要、晨间准备和必要酒店事务确定次日起床与出发，为重点景点保留与其内容及用户兴趣相称的净游览时间；睡眠需要未明确时说明本次采用的假设。

时间预算采用一致的起终点，完整计入参观、补给、步行、交通、排队、等待及必要缓冲，同一时段只计一次。景点停留包含净游览（实际参观、观察和讲解）以及内部通行、补给、排队和缓冲，两者区分表达；景点外交通单列。用户已给出的有效预算直接沿用，并以开放、预约、车次及固定活动为真实约束核对；确需改变已确认安排或预算时，说明依据与取舍，沿用第 2 步的变更确认。

所选安排依赖的供餐及其他服务在采用前核实可用条件，包括早餐供餐窗口与晨间准备的衔接。大型景点或跨午餐参观优先在景区内补给并接入动线；景区内无可用餐饮时核实携食与用餐规定，允许时提示提前准备简餐及可用餐位置；其他情况比较参观前后用餐或调整行程。核实方案依赖的再次入场条件；外出用餐、返酒店及其耗时须有本次需求或实际条件依据。未确定的条件沿用复核或调整办法。

### 2. 收敛并确认行程

根据用户选择调整方案，提交可审核的具体景点与逐日行程，等待用户明确确认。已有有效确认直接沿用；仅给定景点清单或一般性“你决定”，不等于具体行程已经确认。确认后直接进入第 3 步。

中途反馈更新受影响的目标。确需改变已确认行程或关键约束时，先给具体方案及取舍，集中请用户决定，再重算实际受影响的安排与成品内容，保留仍有效的确认。

### 3. 制作完整候选

行程确认后直接制作完整候选，统筹知识深化、内容组织与系列质量，自主完成制作与自检；不设置代表图验证、样张确认、扩量关卡或视觉方向专项授权。

承担识别、观察或讲解作用的具名文物、建筑及其局部插图，在首次制作前取得、查看并使用可靠实物参考，优先馆方、文保机构等来源；核对具体对象、轮廓、结构、数量及残损状态。参考不足时采用有依据的表达并明确示意范围，不把推测细节画成实物事实；普通装饰元素无需逐项准备参考。

当前任务内维护轻量逐页清单，记录页码、版本、实际文件位置、生成结果及待完成修订，形式按需选择。每次生成或修订返回后，核对实际输出存在、可读取且对应目标页，再更新清单；缺失或失败立即记录并处理，必要修订未成功的页面保持未完成，旧图不能代替修订成果。首批及后续每次输出均检查尺寸、比例与清晰度：合格原生输出保留实际尺寸；比例错误或清晰度不足时调整制作，不拉伸变形、裁掉有效内容或仅放大低清图片；精确像素要求在正式审核前落实并复查可读性。

自检按内容与视觉标准查看实际图片：用户能否执行全天与内部路线、理解起止与停留时间、识别对象、找到讲解所指细节并理解标注关系；实际中文正文、字形、局部衔接与整套关系均纳入检查。依据清单形成完整最新候选后进入正式审核；审核、验收和交付核对同一候选的页数、阅读顺序与版本，防止漏页、重复及混入旧图。

研究与制作中，只有独立子任务能实际改善效率或质量时才按需委派；正式审核的角色要求见第 4 步。

### 4. 独立审核与修复

每次正式审核及修复后的正式复审均使用全新、未参与当前候选制作或修复的 Reviewer Agent，默认一名，用户另有指定时按其要求。制作者负责制作、修复与自检；Reviewer 检查实际成品，指出问题位置、表现及影响，给出独立判断。

向 Reviewer 提供当前目标、有效约束、必要事实依据、实物与认可参考，以及逐页清单对应的完整最新候选；修复轮补充变更范围。Reviewer 查看实际高清页面、必要局部和整套关系，有规格处理时检查处理后的页面；判断方法按任务选择。

**系统 PASS 同时满足：** 全部适用的内容与视觉标准成立；行程现实可执行，真实时间约束得到满足；内容覆盖确认范围；知识准确且图像支持识别、理解和观察；候选与逐页清单一致，无缺页或待完成的必要修订；影响行动、理解或有效视觉要求的实质问题已解决。合理早起、必要等待、明确要求的休息或固定用餐，以及有依据并经必要确认的参观调整均可通过。结论说明对应候选、实际核验范围、问题处理结果、确定程度与未验证事项。

首次正式审核完整检查候选；修复后的正式复审覆盖实际影响，并结合完整最新候选判断整套关系。检查范围与修改范围分别判断。有实质问题时按实际影响修复、自检，再进入正式复审，持续到系统 PASS，不预设轮数；共享视觉问题统筹调整受影响的页面后形成完整候选。没有实质问题时停止内部修订，进入第 5 步。

修复持续无改善时重新诊断并调整方法；能力确有缺口时准确说明缺口、已完成范围和现实选项。没有实际成品检查或真正独立审核时，不能宣称系统 PASS；限定范围的复审结论不扩大为整套无问题。

### 5. 系统 PASS 后等待用户验收

系统 PASS 后停止内部修复，按第 7 步的获取要求提供完整最新成品、阅读顺序及准确审核结论，保持候选稳定，等待用户验收。此时尚未完成用户最终验收；用户明确通过后直接进入第 7、8 步，无需再次催促。

### 6. 用户反馈与再次验收

用户反馈先转化为当前目标、判断标准和有效范围。一般性质量反馈时，沿该方向检查整套同类问题、关联影响、遗漏及其他实质问题，修改范围按实际问题确定，反馈只举一页不把检查缩小为该页。用户明确限定修复范围或资源边界时，按该范围修复并完成必要关联检查，保留其余页面的有效版本，提交完整最新候选；范围外发现的问题准确说明，后续处理服从用户当前要求，不自行扩大返工。

修复、自检后沿用第 4 步审核修复循环，再次系统 PASS 后提交完整最新候选重新等待验收，重复至用户明确通过。系统 PASS 以全部适用标准和实际检查结果为依据，范围内修复完成不自动等于整套系统 PASS。

用户带保留通过、接受当前版本或要求停止修订时，保留其条件、对应版本和已知问题，按其明确要求推进；停止修订与接受交付分别判断，用户接受不自动证明所有质量问题已经解决。用户只列出问题而未接受也未停止时，属于反馈。

### 7. 最终交付

按用户验收意见交付对应版本。以用户通过当前渠道可取得、且对应验收候选的实际成品为目标，按可用工具核对所提供文件、附件或链接指向的实际对象，确认内容、页数、阅读顺序和显示结果与验收候选一致。说明实际图片规格、检查范围及仍需临近出发复核的信息；多种尺寸分别说明。

任务实际承诺的图片、PDF、制作资料存档和长期保存分别核对、分别报告；本地文件正确、渠道可获取与用户实际下载是不同证据，按真实检查范围作结论。长期保存只在任务实际要求或已承诺时纳入，不默认新增交付物或下载确认关卡。

文件组织、渲染、字体、导出、压缩、发布及渠道限制由具体工具和相关说明承担，方法按任务决定。交付受阻时说明已完成事项、受阻事项及可行补救，继续处理已获授权且有能力执行的补救；无法验证的获取结果保留未验证状态。文件集合或入口修正保持已验收页面内容；转换造成实际显示变化时检查影响范围，必要时重新审核和验收。

### 8. 流程自检与结束

最终交付后主动自检本次流程，依据实际研究、制作、审核修复、用户验收和交付证据，区分执行遗漏、Skill 表达或机制问题及证据不足，用户带保留通过的条件与已知问题纳入证据。已有规则的执行遗漏先判断如何改进执行与验证；有证据且值得改进的 Skill 问题，提出依据、适用范围、预期改善和验证方式，供后续实施。没有实质改进依据时简短说明。

自检完成后准确说明本次流程结束状态及仍存在的限制。篇幅随证据与问题决定；提出建议不自动触发 Skill 修改，也不重新打开用户已经通过的候选。
