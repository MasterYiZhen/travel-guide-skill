## 1. Skill 目标与范围

Travel Guide Skill v0.1 由用户主动调用，在一个全新、连续的任务中，把模糊或不完整的旅行想法推进为现实可执行的行程，并默认交付一套适合手机现场查看、尽量做到“看图就能玩”的视觉旅行攻略。

Skill 支持两个入口：目的地尚未确定，以及目的地已确定但景点、活动和体验范围尚未确定。模型负责主动研究、提出推荐、组合行程、深化复杂景点、组织内容、生成视觉候选并推动 Review；用户只处理少量会明显改变旅行结果的决定。

v0.1 不处理自动触发优化、中途接手半成品、跨会话恢复或专门的再次调用更新流程；不规定固定城市模板、页面数量、视觉风格、地图服务或来源清单；不建立防篡改、权限、审计、哈希、重型版本管理、资产追踪或多层审批体系。

默认最终交付为手机现场使用的视觉攻略。用户明确要求纯文字或混合交付时服从该要求，但这不是默认路径。

## 2. 核心执行契约

1. **理解旅行想法和固定条件。** 提取出发地、日期、时长、预算、兴趣、节奏、同行人、固定预订、必去／不去和用户已确认事实；只在缺口会显著改变旅行方向时集中提问。
2. **按目的地状态进入对应入口。** 目的地未知时进入目的地发现入口；目的地已知时进入景点、活动与体验范围入口。用户已给出完整必去与不去范围时可直接进入研究与行程组合。
3. **发现候选并确认核心范围。** 目的地未知时研究少量有区分度且现实可行的目的地，给出首选、备选和关键取舍；目的地确定而完整核心范围尚未明确时，先给出“推荐进入核心／条件合适可安排／不建议或已排除”的精炼建议，再集中请用户标记“必去／可以安排／不去／仍需比较”并停止。确认前不得最终确定实际天数与住宿晚数、最终酒店、最终城际交通、详细逐日行程或完整视觉攻略。只有用户已给完整范围，或明确授权核心景点与体验范围也由模型决定、无需确认时，才跳过该门。
4. **主动研究并组合可执行行程。** 核实交通、开放时间、预约、票务、活动规则和临时调整等时效性事实；优先使用当前且权威的来源。以固定活动和用户锁定条件为锚点，组合每日路线、通勤、用餐、缓冲及确有必要的 Plan B，并明确出发前需要更新的信息。
5. **深化复杂景点并组织最终内容。** 对大型博物馆、主题乐园、场馆、公园或其他复杂地点补充入口、内部顺序、停留时间、重点内容、观察点、预约规则和易错点；按旅行复杂度决定总览、每日、专项和深层内容的实际拆分，不固定页数。
6. **按返工风险验证代表性视觉。** 当多图成品共享整体视觉语言、用户提供重要视觉参考或把视觉完成度作为核心验收目标、且错误方向会造成明显批量返工时，必须先生成覆盖实际高风险内容类型的代表性图片。未获整体视觉方向专项授权时，展示实际代表图并等待确认；已获授权时，由模型和唯一独立 Reviewer 查看实际代表图及用户参考。方向成立前不得扩量。
7. **生成完整视觉候选。** 模型自主决定图片数量、顺序、风格、地图形式、构图和实现方法；重要执行信息直接进入最终载体，且从事实到短文案、路线和视觉的转换不得改变原意。
8. **独立 Review、必要修复和交付。** 只使用一个未参与当前候选生成的独立 Reviewer Agent 查看实际代表图或完整候选。有局部实质问题时由 Generator 定点修复，Reviewer 查看修复后的实际成品；整体视觉方向未成立时回退并只重做代表图，方向成立后再扩量；无实质问题时立即停止 Review。随后按清楚的图片顺序交付可直接查看的成品，并把仍需临近出发确认的信息放进攻略或最终提醒。用户只提出局部问题时，只重开受影响范围。

简单旅行可以合并上述相邻步骤；用户已给完整核心范围时不增加范围确认，未满足强制视觉门条件时不增加代表图门。复杂旅行可以增加研究深度、专项内容和代表性视觉验证，但不得新增另一套固定阶段。

## 3. 模型自主权与用户决策点

模型默认自主完成：客观事实研究、候选发现与比较、首选推荐、普通景点排序、交通组合、用餐位置、合理缓冲、必要 Plan B、复杂景点深化、内容拆分、图片数量、视觉风格、地图形式、构图、工具选择和普通修复。模型可自主使用搜索、网页研究、地图、文档读取、图片生成及当前环境中的其他可用能力。

只有以下高影响决定通常需要用户参与：

- 目的地；目的地确定后尚未明确的完整核心景点与体验范围；
- 会显著改变预算、体力、固定活动兼容或核心体验的总体行程取舍；
- 启用代表性视觉验证后，尚未获得授权的整体视觉方向；
- 最终成品是否接受。

用户在当前连续任务中明确说“你决定”“按你推荐的来”或“直接做完整方案”后，该一般授权持续适用于普通后续决定。模型应说明选定方向及最重要的假设，不在每个阶段重复要求确认；但只有用户明确授权核心景点与体验范围也由模型决定、无需确认时，才能跳过核心范围门，只有用户明确授权整体视觉方向也由模型决定时，才能不等待其亲自确认代表图。用户沉默不构成授权。

用户明确确认的条件是当前规划输入。模型发现现实冲突时可以说明风险和可选处理，但不得静默覆盖。

## 4. 独立 Reviewer 契约

- **独立性：** 默认一个 Reviewer Agent；它不得参与当前候选的生成。
- **检查对象：** Reviewer 直接查看实际代表图、完整候选及修复后的实际成品，并获得用户目标、真实使用场景、已确认事实和必要参考成品。Generator 的自评、源码意图、内部坐标或既有 PASS 报告不能代替成品检查。
- **可以指出：** 具体位置上的事实矛盾、会影响执行的重要遗漏、错字、歧义、遮挡、错锚、手机可读性问题、路线第二种读法，以及整体视觉方向问题；说明具体表现、实际影响，并区分局部问题和整体方向问题。报告化或模板化、弱目的地识别、装饰性图片、机械复用构图、无功能空白伴随小字或信息缺失、总览缺少空间骨架、封面内页割裂、不能快速扫图恢复语境，或明显低于用户认可参考维度，都可构成整体方向失败。
- **不得做：** 发明新需求、扩大旅行范围、增加用户未要求的页面、景点或内容、重新设计产品、规定具体布局、配色、组件或修图技术，或为了延长 Review 而制造问题。
- **修复与复查：** 有实质问题时，Generator 只修相关问题；Reviewer 查看新的实际候选，确认原问题是否解决及是否引入明显新问题。
- **停止条件：** 没有实质问题时立即结束，不预设固定轮数。若整体方向未成立，回退到代表性视觉阶段，只重做代表图；按既有视觉授权完成确认或独立 Review 后再扩量，不在完整批次上继续打补丁。

## 5. 最少必要 Guardrails

1. 用户已锁定或明确确认的条件不得被搜索、工具、模型推断或 Reviewer 静默覆盖；发现现实冲突时必须显式提示。
2. 未公布、待确认或需要临近出发更新的信息不得伪造为确定事实，应在最终攻略或提醒中保留其状态。
3. 事实被压缩、改写、拆分、合并或视觉化后，时间、顺序、空间关系、数量、因果和动作状态不得改变。
4. 参考成品只用于用户明确认可的体验或视觉目标，不作为旅行事实源，也不机械复制其城市风格、结构、页数或组件；被认可维度必须实际进入代表图判断和 Reviewer 对比。
5. Review 必须查看用户实际会看到的最终输出；修复后必须查看新的实际成品，不能用 Generator 说明或局部检查结论代替。

## 6. 输出与非目标

**正常最终输出**是一套按现场使用顺序组织、可直接查看的视觉旅行攻略，默认面向手机竖向浏览。其内容根据任务实际需要覆盖总体行程、每日主线、交通与空间衔接、预约／票务、固定活动、复杂景点内部玩法、重点内容、必要备选和出发前更新提醒。用户明确要求时，可改为纯文字或混合交付。

**简单旅行或核心范围已经完整的任务**应合并相邻步骤，减少页面和中间产物；未满足强制触发条件时不启用代表性视觉验证。**复杂旅行**可增加专题研究、复杂景点深层内容和代表性视觉验证，但仍由模型自主决定最小充分拆分，不固定页面数，也不增加额外 Reviewer。

事实整理、专题笔记、内容提纲或其他中间文件都不是强制产物。默认保留在当前任务上下文中；只有资料复杂、来源很多或确有复用价值时才创建。

v0.1 明确不实现：自动触发优化、中途接手与跨会话恢复、专门的后续更新工作流、固定视觉模板或地图服务、固定多 Agent／多 Reviewer／Review 轮数、复杂打包与资产管理、安全权限审计体系，以及默认脚本。只有在仓库检查证明某个确定性任务无法通过说明和现有能力可靠完成时，Codex 才可先说明必要性并建议脚本方案，不得直接扩大实现范围。

## 7. 基础 Eval 集合

以下保留最初的五个基础案例；本轮新增回归以 `evals/evals.md` 为完整、当前的检查集合，不在本文重复展开。

### Eval 1｜目的地未知的三日旅行

- **输入：** “三天出行，出发地和预算已给，喜欢历史与美食，目的地未定；按你推荐的来，直接做完整方案。”
- **期望关键行为：** 研究少量有区分度的目的地，明确首选与主要取舍；一般授权可用于选择推荐目的地和普通决定，目的地确定后若完整核心范围仍未明确，则进入核心范围确认门；不为普通决定反复询问。
- **失败表现：** 只罗列热门城市、不作推荐；跳过现实可行性研究；在每个阶段要求确认；或把一般授权解释为可跳过尚未明确的核心范围并直接生成整套攻略。

### Eval 2｜目的地已知时的一般授权与核心范围授权

- **输入 A：** “目的地已定，最多四天，不知道玩什么；偏好博物馆、城市历史和轻松节奏；直接做完整方案。”
- **输入 B：** “条件同上；核心景点和体验范围也由你决定，不需要我确认。”
- **期望关键行为：** 输入 A 先得到分层、有判断的范围建议和一次“必去／可以安排／不去／仍需比较”集中确认，然后停止；确认前不最终确定天数、晚数、酒店、城际交通、逐日详案或完整视觉攻略。输入 B 可采用推荐范围继续，不为形式确认。
- **失败表现：** 给出无优先级清单；把输入 A 的“直接做完整方案”当作跳门授权并直接输出完整方案；或对已作专项授权的输入 B 仍强制确认。

### Eval 3｜简单周末游不过度流程化

- **输入：** “本地两天周末游；完整核心范围只含一个指定景点，不增加其他打卡点；没有重要视觉参考，直接做完整方案。”
- **期望关键行为：** 因范围完整而跳过核心范围确认，合并相邻阶段，完成必要研究和紧凑行程，直接生成少量清楚的最终候选并交给独立 Reviewer 查看，无实质问题即结束；不创建事实包、专题文件、代表页门禁或多轮审批。
- **失败表现：** 产生大量问题、文件、角色、状态或 Review 仪式；固定生成多张专项图；流程成本明显高于旅行本身。

### Eval 4｜固定活动与复杂场馆

- **输入：** “四天旅行，酒店和往返交通已定，其中一晚有不可移动的演出，另有一个多楼层大型场馆；部分入场规则尚未公布。”
- **期望关键行为：** 把固定活动作为时间锚点，主动核实当前权威事实；倒推交通、用餐、缓冲和必要备选；深化大型场馆的入口、内部顺序、重点内容与易错点；未公布信息保持状态并进入最终提醒。
- **失败表现：** 优化或移动用户固定活动；伪造入口／门号；只给景点名单；或因复杂而自动建立多 Reviewer、多层审批和固定大套件。

### Eval 5｜独立 Reviewer 触发定点修复

- **输入：** 一批已生成的视觉候选，其中一页存在明显的时间—地点错锚，另一处有错字或遮挡，其余页面方向成立。
- **期望关键行为：** 未参与生成的 Reviewer 直接查看实际图片，指出具体位置和影响；Generator 只修相关页面或区域；Reviewer 查看修复后的实际成品，无实质问题后立即停止并交付。
- **失败表现：** Reviewer 采信 Generator 自述而漏检；把局部问题扩大为整套重新设计；新增用户未要求的内容；固定执行多轮；或未查看修复后的实际输出就宣告通过。
